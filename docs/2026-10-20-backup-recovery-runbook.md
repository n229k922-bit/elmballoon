# 非公開バックアップと復元確認

実施日: 2026-10-20。対象は取得済みLINEナレッジ原本と **テスト** D1/KV。本番環境の更新・復元・送信は行っていない。

## 実施結果

- 取得済みナレッジ237ファイル、テストD1 SQL、テストKV JSONの計239ファイル／129,039,830 bytesをAES-256-GCMで暗号化した。
- 暗号化ファイルSHA-256: `43d25bbc1e26b2c86bb182d832e19f0a290e8660ce27266e73233c2ef0f6cf37`。
- 復号後の全ファイルのサイズ・SHA-256を検証した。D1 exportを隔離したメモリSQLiteへ読み込み、integrity_check = ok、35テーブルを確認した。注文2件、過去資料63件、送信キュー10件、返信案7件。
- テストKVは列挙→値取得→再列挙の読取操作で0キー。前後の列挙一致を確認。KVは複数キーのトランザクションスナップショットを保証しないので、更新がない時間帯に取得する。
- バックアップは `%USERPROFILE%/.codex/private/backups/2026-10-20-practice/knowledge-test-runtime.elmbak`。鍵は別フォルダ `%USERPROFILE%/.codex/private/backup-keys/2026-10-20-practice.key`。どちらもGit管理外。鍵内容を画面、チャット、コマンド引数へ出さない。
- SQLの隔離復元はATTACH/DETACH、ファイル読書き関数、危険なPRAGMAを拒否する。リモートへの書込処理は存在しない。

**残る確認:** 同じPCだけでの保存はPC故障に耐えない。暗号化ファイルを別端末／保管先へ移し、鍵を別のアクセス管理された場所へ保管し、その端末で読戻しを確認する必要がある。今回、別端末保管や本番リモート復元の合格は主張しない。

## 再実行

1. 注文処理の更新を止めた時間帯に、承認済み対象のD1をWranglerのread-only exportで非公開フォルダへ保存する。出力に署名付きURLが出るためstdout/stderrを公開しない。
2. `tools/backup-manager-kv.mjs` に非公開JSON設定ファイルを渡す。設定は `wranglerPath`, `wranglerConfig`, `namespaceId`, `output`。現実装は確認済みテストKVだけ許可する。キーと値は出力しない。
3. `tools/backup-manager.mjs create PRIVATE_CONFIG.json` を実行する。設定は `sources`（原本フォルダ配列）, `sqlFile`, `kvFile`, `output`, `keyFile`。初回だけ `generateKeyFile:true` で鍵を生成できる。既存鍵や既存アーカイブを上書きしない。環境変数 `ELM_BACKUP_KEY_BASE64` を使う場合も値をログへ出さない。
4. `tools/backup-manager.mjs verify PRIVATE_CONFIG.json` で暗号認証・全ファイルhash・隔離SQL復元を再確認する。設定に `archive` と `keyFile` を指定する。出力は件数・テーブル名・hashのみで本文や個人情報を含まない。
5. 別端末へ暗号化ファイルと鍵を別々に移し、同じverifyを実行する。結果と日時を非公開運用記録へ残す。

作成は元ファイルを変更しない。原本の順次読取であるため、取得中に原本が更新される環境では再取得する。D1/KVと原本全体の同一時刻スナップショットではない。

## 復旧判断

本番へ直接上書きするコマンドは提供しない。復旧が必要なときは、送信停止→現状の別バックアップ→隔離環境に復元→注文数量・日時・対象顧客・送信済み状態・鍵とセッションの失効確認→差分確認→切替判断の順で行う。特に古い送信キューやログインセッションの無条件再利用を避ける。過去の送信済みメッセージを再送しないことを実機で確認してから再開する。

## readinessの扱い

`getManagerReadiness` は既存の設定確認と別に `operationalReadiness` を返す。今後14日間の受付上限、本人確認済み履歴、実店舗の営業予定照合、画像撮影設定、画像実確認、バックアップ別端末復旧確認、スマホ受入を分ける。画像設定があるだけで画像合格にせず、実測できない項目はunknownのままにする。店舗上限や予定、履歴の本人確認を開発者の推測で埋めない。

## 店長が入力する画面

`/manager/setup` と `/api/manager/setup` は既存の店長認証を使う。今後14日間の未設定を表示し、日ごとの制作時間・配達件数・注文件数を入力、確認画面を経てその日だけ保存する。空欄を0にせず、予約済みの作業量を下回る上限変更は既存の受付枠保護で拒否する。

営業予定を実店舗と照合した場合は、実確認日・対象最終日・照合資料と内容を入力し、ログイン担当者・記録時刻とともに監査ログへ残す。予定やホームページを変更する操作ではない。画像、別端末復旧、スマホ操作の合格を設定するチェックボックスは用意していない。
