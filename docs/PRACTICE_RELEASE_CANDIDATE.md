## 是正済み

- **数量と対象**：1→2/2→1、全角・一個/二個・ひとつ/ふたつ、変更対象未確定、取消、小数・負数・0、人数配分、複数訂正、印字文、重複Webhookを検証。専用43ケース成功。複数注文の曖昧な変更は両方とも不変、確認済み数量は変更案として保持する。
- **文脈**：色比較相談を候補のまま受け止め、日付が明確な使用日/受取日は別々に保存する。別注文の日付を新しい希望日だけで選ばない。
- **カルテ**：認証付きのHTML印刷/保存とPNG保存。数量・確認状態・未承認変更を明記し、長すぎるPNGは不完全に切らずHTML印刷へ案内する。写真の個数を注文数へ転用しない。
- **画像**：注文/顧客/発言/チャネルの照合を経て固定LINE APIから取得。非公開KVで365日保存し、再読込でハッシュと画像形式を検査する。壊れたPNGの展開、別注文混在、期限切れ、保存失敗、再試行上限を検査。最長8MiB、PNG展開32MiB、画像寸法制限。元LINEから既に取得不能で保存もない画像は復元できたことにしない。
- **履歴**：50件ずつ追加読込。同時刻の123件でも重複・欠落なく取得する。過去資料を一括で本人確認済みにする変更はない。
- **営業日画像**：実ページの環境・日付・状態・時間を撮影側でも照合し、同じ表示の対象領域だけをPNG化する。画像展開/CRC/保存読戻しを検証。営業日更新と監査は同一トランザクションで、保存失敗時に完了画像を返さない。
- **HP画像差し替え**：具体的な対象と素材から、元サイトを変えず新旧hash・寸法・alt・復旧コピー付きの隔離変更案を生成する。実際の掲載は差分確認後。JPEG/WebPやsrcset等の未対応パターンは通さない。
- **バックアップ**：取得資料と実テストD1/KVを239ファイル/129,039,830 bytesとして暗号化し、読戻しと35テーブルのSQLite隔離復元を確認した。orders2/imports63/outbox10/drafts7は元テストD1の読取集計とも一致。鍵は別のprivateフォルダに保存してGitへ入れない。
- **準備画面**：`/manager/setup` で日別上限を確認→保存。空欄は未確認、予約を下回る減枠を拒否。営業予定を照合した日/担当/対象期間/資料を記録する。通常店長画面に入口がある。
- **監視**：認証付き `/api/manager/health` は定期処理の停止、DB障害、未処理受信、失敗/結果不明、再開中の長時間送信待ち、画像保存の失敗を区別して異常を返す。外部から定期確認し通知する設定は別途必要。
