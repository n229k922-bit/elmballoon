# 実会話の整理用カルテ項目

2026-10-19。既存 ORDER_CARD_WORKFLOW.md と migrations/0010_customer_order_records.sql、0013_manager_v2.sql を確認して整理した資料。稼働DBへ追加・取込済みという意味ではない。

## 管理単位

顧客 → 注文・相談 → 商品明細／予定／変更履歴／根拠。一人の複数注文を別にする。来店相談と将来の相談も商品注文の確定件数へ加算しない。支払い・領収書が複数注文をまたぐ場合は対象未照合の会計メモとして保持する。

## 共通項目

|区分|記録する内容|
|---|---|
|顧客|表示名、確認できた氏名、電話番号、必要な住所、本人照合状態。記載のない情報は未確認|
|案件|注文／見積相談／来店相談／将来相談、用途、贈る相手、既存カルテとの重複候補|
|商品明細|商品番号・参考画像、数量、サイズ、形、色、キャラクター、文字・名前・字体、商品ごとのメッセージと差出人|
|金額|希望予算と見積を別にし、単価／合計／内訳／税込不明を明記。過去価格は現行価格にしない|
|予定|使用日、相談来店、受取、配達、発送、支払来店、貸出物回収を別の予定として保持|
|場所|受取方法、届け先、建物・階・連絡先。場所の質問中と確定を分ける|
|進行|提案、顧客希望、店舗了承、制作、完成写真、受渡しを別々に記録|
|会計|支払方法、予定、入金確認、領収書の依頼／発行／対象注文。依頼や来店だけで入金済みにしない|
|判断待ち|不足情報、未回答事項、金額不一致、次に確認すべき内容。過去の案件から自動催促しない|
|履歴と根拠|発言者、画面表示日付、引用または要約、画像・本文の参照先、確認範囲、最終確認日、変更前後|

項目ごとに「顧客希望」「店舗提案」「顧客了承」「店舗了承」「実施明示」「未確認」「矛盾・要照合」を分ける。記録の確認状態は案件の進行状態とは別。画面に年がない日付へ年を推定補完しない。

## 継続イベントとお届け先の整理

注文者・支払者・贈る相手・届け先店舗は別の役割。複数の注文者が同じ店へ贈っても顧客や支払いを統合しない。注文者の住所を配達先と取り違えない。

|単位|管理項目|
|---|---|
|お届け先店舗|正式名・表記候補、郵便番号・住所・建物・階・入口、受取担当者と業務用連絡先、搬入可能時間、設置場所、回収条件、各情報の出典・最終確認日|
|継続イベント|届け先と対象人物、周年／誕生日／その他イベント、正式な記念月日とその根拠、毎年開催かの確認状態、注文者との関係|
|各年の開催・注文|開催年、実開催日時、配達日時、商品・写真・金額・文字入れ・差出人、設置・回収・決済、前年からの変更|

個人の誕生日と誕生日イベントの開催日と配達日は別。周年記念日と周年イベント開催日も別。配達日だけから記念日を作らない。年月日不明はそのまま残す。翌年の周年数・年齢・文字を自動加算しない。

継続可能性は「可能性あり・未確認」「毎年開催と確認」「今回限りと確認」「不明」を分ける。ユーザーが示した業務上の可能性を、各過去案件の毎年開催の証拠にはしない。

住所や担当者の変更は旧注文の記録を上書きせず履歴化。店舗の名称一致だけで同一店舗にせず、移転・同名店・支店・店名変更を照合する。店舗マスターは最新版候補、各注文は当時了承された届け先の写しを持つ。回収先・請求先も配達先とは別。

リピート相談時は関連する過去注文と届け先候補を店長へ提示し、「今回も同じお届け先か」「開催日時・受取担当・搬入条件に変更がないか」を確認。前年価格・例外の夜間対応を今回の確約にしない。他の注文者の氏名・予算・文面・決済を顧客への返信へ混入させない。

店長用画像は前回写真・用途・当時の日時と金額・今回確認する変更点を中心とし、住所詳細は配達確認時の限定表示。未確認情報は画像でも未確認と示す。毎年の自動注文・自動連絡・定期通知はこの定義追加では開始しない。

## 保存運用

- 実名・電話・住所・会話URL・原本画像・実カルテはGit外の非公開領域。匿名の項目定義だけをGit管理する。
- 店長への要約は「誰の／何の／いつの／何を判断するか」を中心にし、内部IDや管理状態の英語を出さない。
- 整理版カルテは原本の追記資料。旧68件へ重複確認前の上書き・件数加算をしない。
- 今回はローカル資料整理まで。サーバー取込、本人ID紐付け、返信への自動適用はしていない。

## 既存実装との注意点

0010には項目単位の状態・出典・変更履歴がある。一方、同一顧客で有効案件を一つに限定する索引もある。0013には複数のmanager_ordersと別々の制作・受渡し・支払い状態がある。資料の整理だけで実システム全体の複数注文対応が完了したとは判断しない。将来の取込時には実際に使う経路と案件選択を検証する。
