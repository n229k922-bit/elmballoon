# 店長が番号で自然に相談できる統括

## 表示原則

通常表示は「お客様／商品」「確認してほしいこと」「変更前→変更後」「番号の選択肢」。日時・金額・数量・背番号・電話など業務に必要な数字は残す。内部の注文番号・返信番号・英語状態・版番号・開発用コマンドは出さない。内部識別子、出典、監査、認証は削除しない。

対象選択と判断は別画面。番号だけで複数注文を一括処理しない。店長ごとの選択・期限・注文の版を確認し、古い入力では変更しない。新しい話題へ移ると前の選択を無効化する。過去の「1」を新しい判断の承認として流用しない。

## 表示の例

返信：ご連絡への返事を作りました。お客様名・商品・返信文を示し、「1 この内容で送る／2 文章を直す／3 あとで確認」。送信開始前は「返信しました」と言わず、失敗・結果不明も区別する。

内容変更：受取日などを「変更前」「変更後」で示す。用途の日付が変わらない場合はその旨を明記する。返信承認と注文変更の承認は別。

店休日：お休み・通常営業に戻す・営業時間を変える→日付→時間（必要時）→最後に確認。お客様との約束は変えない。カレンダー表示を実際に検証・撮影できた場合だけ画像を送り、保存だけなら画像確認は未完了と伝える。

画像：場所を選ぶ→対象商品・ページを教える→新しい写真を送る→変更依頼を確認。画像を受け付けたこととホームページで公開できたことを分ける。現在の実装は依頼とLINE画像の参照の保存までで、画像取得・プレビュー・Git上の差し替え・公開は未接続。公開完了とは表示しない。

過去情報：当時の商品・希望・価格を参考表示し、現在の仕様へ勝手に流用しない。技術的な保存場所・識別子は通常表示に出さないが、保存された出典は保持する。

## 反映範囲

この変更はローカル実装・検証。実店舗のLINE設定・Webhook・ホームページ・顧客送信は変更しない。番号会話専用の追加migrationは不要。テスト公開前に既存migrationの適用状況を確認し、テストアカウントで選択・取消・期限切れ・切替を実機確認する。旧コマンドは互換のため内部に残すが、通常の案内へは出さない。

## 期限通知

期限通知は東京時間の月〜金10:00〜16:00に限り、土日、日本の祝日、登録された店休日は次の営業日に回す。同じ未対応案件は最大1日1回とする。注文者名・商品・希望日・数量・未判断事項を表示し、期限も日本語の年月日時刻に整える。通知からは「返信待ち」で案件を番号選択できる。
