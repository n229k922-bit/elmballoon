# 統括リッチメニュー テスト運用仕様

## 目的

「バルーン統括」のテスト用公式アカウントで固定ボタンから依頼を開始し、AIが依頼種類を取り違えず、必要事項・新旧差分・実行確認を順番に案内できることを検証する。

本仕様の段階では、実店舗の公式アカウント、公開中のホームページ画像、確定済み注文データには反映しない。

## 使用するアカウント

| 役割 | テスト用公式アカウント | 用途 |
|---|---|---|
| お客様側 | 注文担当🤖 | 注文開始、ヒアリング、顧客向け返信の確認 |
| 店長・統括側 | バルーン統括 | 注文確認、変更依頼、返信承認の確認 |
| 実店舗 | 霧島市バルーン工房elm・balloon | この段階では接続・変更しない |

## リッチメニュー案

2行×2列の4ボタンとし、ボタンは必ず次の固定文言を送る。

| ボタン | 送信する固定文言 | 動作 |
|---|---|---|
| 日付変更 | `日付変更依頼` | 注文日程か店舗営業日のどちらを変えるか確認する |
| 画像差し替え | `画像差し替え依頼` | 対象商品・ページと新画像を順番に確認する |
| お客様へ返信 | `お客様への返信依頼` | 注文カルテと送信文を確認し、送信前プレビューを作る |
| カルテ確認 | `カルテ` | 最新の注文カルテを読み取り専用で表示する |

## 共通ルール

1. ボタンを押した時点では、データ変更・画像公開・顧客送信を行わない。
2. 店長ごとに1件だけ「入力中の依頼」を保持する。
3. 入力中の依頼は30分で失効する。
4. 別のボタンを押した場合は、以前の入力を破棄する前に切り替え確認を出す。
5. `取消` でいつでも終了できる。
6. 実行前に必ず対象、新しい内容、変更前の内容を表示する。
7. テスト段階では `確定` を押してもテスト記録だけを更新し、本番データへ反映しない。

## 日付変更依頼

### AIの最初の返信

```text
日付変更のご依頼ですね📅

どちらの日付を変更しますか？

1：お客様の注文・受取日時
2：店舗の営業日・営業時間

数字で「1」または「2」と返信してください。
取消する場合は「取消」と送ってください。
```

### 注文・受取日時を選んだ場合

```text
以下の内容をお送りください。

・注文カルテ番号：
・変更したい項目：
・変更後の日時：
・理由や補足：

例：
・注文カルテ番号：KABC123
・変更したい項目：受取希望日時
・変更後の日時：10月3日 15時頃
・理由や補足：お客様からLINEで変更依頼あり
```

受信後は注文カルテの現在値を読み、次のように表示する。

```text
【日付変更の確認】

対象：注文カルテ KABC123
項目：受取希望日時

変更前：10月2日 14時頃
変更後：10月3日 15時頃

テスト記録へ反映する場合は「確定」、修正する場合は修正内容、取り消す場合は「取消」と返信してください。
```

### 店舗営業日を選んだ場合

対象日、営業・休業・営業時間変更、変更後の時間、理由を確認し、既存カレンダーとの新旧差分を表示する。

## 画像差し替え依頼

### AIの最初の返信

```text
画像差し替えのご依頼ですね🖼️

最初に、差し替える対象を教えてください。

・HPの商品番号：
・対象ページまたは掲載場所：
・差し替え理由：

対象を確認した後に、新しい画像の送信をご案内します。
取消する場合は「取消」と送ってください。
```

対象確認後だけ画像を受け付ける。画像だけが先に届いた場合は保存せず、対象商品を先に確認する。

```text
【画像差し替えの確認】

対象商品：バルーンアレンジ36番
対象ページ：商品詳細ページ
現在の画像：確認済み
新しい画像：受信済み

テスト用の差し替え依頼として記録する場合は「確定」、取り消す場合は「取消」と返信してください。

※この段階では公開中のホームページ画像は変更されません。
```

## お客様への返信依頼

### AIの最初の返信

```text
お客様への返信文を準備します💬

・注文カルテ番号：
・送りたい内容：

を続けてお送りください。
送信前に、宛先と文章を確認用に表示します。
```

お客様への送信は、テスト用注文担当アカウントのテスト顧客だけを対象にする。宛先・注文カルテ・送信文を表示し、確認操作後だけ送信する。

## カルテ確認

既存の `カルテ` 操作を利用する。変更は行わず、最新カルテの番号、進捗、確認済み項目、不足項目、変更待ちを表示する。

## 想定外入力への対応

| 状況 | 動作 |
|---|---|
| 必要項目が不足 | 不足項目だけを再質問する |
| 複数のカルテが該当 | カルテ番号の候補を表示して選択を求める |
| 存在しない商品番号 | 画像を受け付けず、商品番号またはページURLを再確認する |
| 画像が先に届く | 対象商品を先に確認する案内を返す |
| 30分以上経過 | 依頼を失効し、もう一度ボタンを押すよう案内する |
| 別のボタンが押される | 現在の依頼を切り替えるか確認する |
| 同じ内容が連続送信される | 1件としてまとめ、二重登録しない |

## テスト順序

1. 固定文言を手入力し、各依頼モードの最初の案内を確認する。
2. 正常な入力で確認画面まで進める。
3. 空欄、順番違い、画像先行、存在しない番号を確認する。
4. `取消` と30分失効を確認する。
5. 同一依頼の連続送信で二重登録されないことを確認する。
6. テスト用注文担当アカウントとの返信送受信を確認する。
7. 上記が通過してから、バルーン統括のテスト用リッチメニューへ4ボタンを設定する。
8. 実店舗公式アカウントへの反映は、店長確認と明示的な公開許可を得てから行う。

## 公開前の合格条件

- 依頼種類を取り違えない。
- 対象カルテ・商品が確定するまで変更しない。
- 変更前と変更後を必ず表示する。
- `確定` 前には外部送信・公開・データ更新をしない。
- 同じ依頼を二重処理しない。
- テストデータと本番データが混ざらない。
- 操作履歴に依頼者、対象、実行結果、時刻が残る。
