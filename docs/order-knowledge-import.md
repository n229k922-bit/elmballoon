# 過去カルテを安全に業務へつなぐ取込準備

## 実アカウントへ影響させない収集（2026-10-05）

収集→非公開カルテ保存→匿名化した知識候補→テストの確認待ち資料→店長レビューを分離する。本番の応答設定・Webhook・トークンを変更せず、お客様へメッセージを送らない。未読トークは開かない。既読への影響を避けるため、未読を開かないという条件を満たせない場合は収集を止める。

スクロールで確認した開始日・終了日、添付を読んだか、途中で読み込みが止まったかを残す。見えていない全履歴を確認済みとしない。顧客の言葉と店舗の回答を区別し、価格・納期・例外対応を全注文の規則へ自動昇格しない。個人情報は非公開カルテのみ、Gitには匿名化済み資料と実装だけ。

保存済み資料のローカル検証は68件・知識候補11件。これは10月5日の新着会話収集やサーバー取込完了ではない。既存サーバー取込63件との差分は別途確認する。

AI受付案内は MANAGER_TEST_MODE=true と AI_DISCLOSURE_ENABLED=true が両方ある場合だけ、最初の案へ追加する。現時点では承認送信フローを維持し、自動送信へ変更しない。スタッフが実際に確認していない内容を確認済みと案内しない。

`node tools/build-order-knowledge.mjs --validate` は過去カルテを解析し、件数だけを表示する。DB書込み・顧客連絡は行わない。

`node tools/build-order-knowledge.mjs --output order-knowledge.private.json` は要確認データを作成する。同名ファイルがある場合は上書きしない。出力には氏名・電話・住所を含む元の文章が入るため、社内の保管先で扱う。Dropbox配下は同期対象になり得る。ファイル権限だけではWindowsのアクセス制御は保証できない。

## 記録の扱い

- A〜Cの各カルテ、Dの限定情報を別の取込候補として保存する。Eの本文未確認一覧は注文として生成せず、元資料の全文に残す。
- ファイル名・見出し・行番号・内容ハッシュを保存し、根拠へ戻れるようにする。同じ内容の再生成は同じIDになり、内容変更は別の確認対象となる。
- 全件 `needs_review`、顧客ID未設定で生成する。表示名が似ているだけでLINEユーザーへ結びつけない。担当者による本人の照合、原文の確認、明示的な有効化が必要。
- 元資料の「完了」「仕様確定」等は原文として保存する。支払い済み・納品済みなどの稼働状態へ自動変換しない。六か月全履歴の完全性は未検証。
- 匿名ナレッジは規則の候補に留める。過去価格、配達範囲、在庫、制作日数を現在の確約条件として使わない。元資料が匿名化済みという前提も公開前には担当者が確認する。
- これは追加学習ではなく、照合・レビューに使う資料整備。生成後は認証済み統括画面の「過去カルテの取込み・確認」からサーバーへ取り込める。取込み直後には返信参照対象にならない。

出力の `records` は `manager_imports` 用の準備データ。サーバーは内容ハッシュと列を検証し、ファイル内の承認・本人紐付けを信用せず全件確認待ちにする。「履歴紐付」で本文と本人を照合し、「履歴承認」後だけ同じ顧客の参考資料として検索する。`private_source` と `knowledge_candidates` を顧客返信に直接投入しない。

検証：`node --test tools/test-order-knowledge-import.mjs`

## 店長による履歴照会（2026-10-01）

- 認証済み統括画面の「統括に過去の注文を尋ねる」で「山田さんの過去の注文を確認したい」「過去注文 080-0000-0000」等を入力する。名前・商品・電話の保存文字による検索であり、任意の日本語を理解する学習済みAIではない。
- 候補の「過去の内容を読む」で原資料・未確認状態・当時の条件を読む。検索は本人の特定や自動紐付けを行わない。
- 今回の注文を選び、「選択中の注文のお客様と照合」して原文と本人を確認した後、「本文と本人を確認済みとして保存」。以降、同じ顧客IDの案件へ参考情報を提示する。同姓同名や似た表示名を理由に承認しない。
- 統括コマンドは「履歴詳細 legacy番号」「過去情報 M番号」にも対応する。店長LINEへ接続したv2環境でも同じ処理を使う。テスト環境は店長LINEの認証・通知先設定が未接続であり、LINE実機での動作は未確認。
- リピーターは本人紐付け・内容確認済みの取込資料と、同じ顧客IDの終了済みカルテを店長向け通知案およびカルテの「過去情報」に添える。最新各3件・要約表示に限定し、詳細は検索して確認する。
- 過去の住所、価格、在庫、納期、名前の綴りは今回も同じとは限らない。現在の項目やお客様向け返信へ転記しない。手動受付は案件ごとに別の顧客識別子を作るため、電話番号だけでは自動リピーター判定しない。
- 2026-10-01、保存資料から63件をテストD1へ確認待ちとして取込済み。自動本人紐付けは0件。元資料に記載された6か月の全履歴の確認完了を保証するものではない。氏名・電話・住所を含む取込データはGitへ保存しない。
