# 拡張検証からの実装順序と合格条件

今回の受付本体は未修正。下記は再現結果に基づく改修仕様であり、対応済みの機能一覧ではない。全組合せを有限の24例で網羅したとは言わない。

## 先に直す項目

| 優先 | 改修 | 根拠 | 合格条件 |
|---|---|---|---|
| 最優先 | 情報抽出より先の会話意図ゲート | intent-diagnostic の6不合格 | 安全・苦情・人へ交代・雑談・終話・見送りでは通常質問とフィールド更新を止め、必要な引継ぎだけを行う |
| 最優先 | 一通内の複数注文を分割、難しければ全更新保留 | EXP10/EXP24、EXP-G01 | 旧注文追記と新相談で予算・数量・日時・方法を別保持。片方の終了で他方は止めない |
| 最優先 | 日時の変更提案を一組で保持 | EXP20最終保存は旧日付31日と新時刻18時 | 新希望30日18時・旧希望31日12時・使用日11月1日を別保持。月不明なら未確定として尋ね、時刻だけ反映しない |
| 高 | 苦情・交代要求の状態を次の発言へ持続 | EXP12〜14 | 通常の商品質問へ戻さない。謝意・事実確認・担当引継ぎを優先。責任・補償・返金額を無根拠に断定しない |
| 高 | 未成立相談の終了ライフサイクル | EXP11、EXP-G03/G06 | お礼・仕様の訂正だけで再開せず、明示的な再相談だけで再開。成立済み注文の取消とは分ける |
| 最優先 | 安全事故の専用処理・優先キュー | EXP-G05、25件目が初回処理されないことをmanager-queue-diagnosticで再現 | 通常受付・営業時間待ちから分離。承認された安全文面と人への通知を使う。医療処置・連絡先を推測しない。具体文面は公的情報の確認と別審査が必要 |
| 高 | 単一店長の判断依頼を最新版へ集約 | 追記ごと新しい通知になり得る静的監査 | 一注文一判断の最新版が明確。新しい条件で旧案は送らず、顧客名・商品・日時・判断点を短く表示。内部番号は通常画面に出さない |
| 高 | 通常通知と緊急通知の営業窓分離 | 初回通知の営業窓は未合格 | 通常は指定の平日営業窓、緊急は明示した別経路。初回・再通知・再試行の各経路を同じ方針で検査 |
| 中 | 長い一覧のページングと顧客別公平性 | 現行24件は874文字で切れず。長文切れは潜在リスク | 長文名・大量案件でも全件へ到達。大量投稿者が他人の緊急案件を塞がない |
| 中 | 実並行・複数端末・ロック期限試験 | SQLite模擬環境では未検証 | 同一店長の複数端末、120秒リース境界、送信開始後の訂正、通信断でも誤承認・誤送信なし |
| 高 | 否定・比較・除外の抽出強化 | EXP01赤を入れない、EXP02置く方、EXP03商品番号ではない | 除外色を有効色に入れず、比較質問を選択済みにしない。商品番号の否定から番号を抽出しない |
| 高 | 人別・素材別の子明細 | EXP05/EXP17 | 名前・背番号・色・包装・大きさ・予算を明細別に保持し、1人の訂正を全員に適用しない。原文保存だけで明細確認済みとしない |
| 高 | 匿名名札・画像共有の権限状態 | EXP07/EXP22 | 顧客確認のみ、限定グループ、SNS不可を別状態として保持。投稿・公開前に範囲を再確認 |
| 中 | 金額表現の幅と単価合計の整合 | EXP06の2万から3万、EXP09の1つ6000円 | 幅の下限と上限を保持。単価が不明に変わった際、過去totalの状態を矛盾して流用しない |

## 実装の構造

受信保存 → 意図分類 → 注文の分割・対象確認 → 変更候補の抽出 → 相談状態・変更提案の保存 → 必要な質問または店長判断 → 対象と版を固定した承認 → 送信直前の再確認。

分類の確信が足りなければ、既存注文へ一部だけ上書きせず、短い確認に止める。生成AIを追加しても分類結果は候補とし、価格・在庫・枠・本人照合・返金の決定権には使わない。

## ナレッジの運用

- 実会話に基づく匿名パターン、創作拡張、実コード出力、役割エージェントの提案を別種として保持する。
- 年齢・性別はテストの多様性の軸。性格・好み・購買力・応対優先順位を推測する根拠にしない。
- 場面と本人が示す希望に基づいて尋ね方を変える。高齢だから一律に説明を増やす等の固定化をしない。
- 実店舗の価格・在庫・営業時間・配送範囲へ仮想の店長判断を昇格しない。
- 本体修正後は同じ96発言と6意図診断を再実行し、修正前後差分を残す。既知問題の診断が失敗し続けるなら本番合格にしない。
