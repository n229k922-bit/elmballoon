# 会話スタイルと店長操作の検証

2026-10-20に `tools/test-conversation-personas.mjs` を実行。25ケース、顧客60ターン、238判定が合格した。実行結果は実際の会話処理・受付キュー・店長コマンド・送信待ち状態を検証したもので、外部LINEへの配信確認ではない。

ケースは取得した実会話から業務場面を抽出して匿名の架空文面で作成した。短文、長文、色の迷い、急ぎ、不満、誤字、専門用語への不慣れ、省略語、代理人、脱線、お別れの装飾、リピーター、見積、領収書、支払来店、配達後のお礼、在庫と代替、来店遅刻、受取候補、時刻変更、商品別名入れ、見送り、安全相談、同一人の別注文を扱った。年齢や性別から性格を決める設計にはしていない。

通常24ケースも店長役の操作を実行した。確認待ち一覧から番号で返信案を選び、承認するケース、2で全文を修正して承認するケース、3で保留するケースがある。操作後は実データベースの保留状態、修正本文、対象返信だけが送信待ちになることを確認した。人の確認が必要な安全相談・苦情・弔事・見送りは保留として表示する。

25番目は店長1人に12人の注文が重なる場合を検証した。最初の数字だけでは送信せず、対象選択後も送信せず、修正を確認後に1件だけ送信待ちへ登録した。承認の重複入力で送信を増やさず、12人の注文は別々に保持された。配信先はテスト内のモックだけである。

初回に、次の流れの質問、返答を待ってほしい連絡、終了の挨拶、条件付き在庫照会の色保存、名入れの訂正が不適切な受付へ戻る問題を検出した。製品側の修正後に再実行して合格を確認した。複数注文が開いており、直前に店側の対象確認がない状態で「それは赤」と届いたケースでは、注文を決め打ちせずどちらの注文か聞き返し、どちらのカルテにも色を保存しないことを確認した。

表示画面は `http://127.0.0.1:8789/`。同一PC内のログを約1秒ごとに読み込み、検証回・会話・ペルソナで絞り込める。新しい検証実行を追う場合は「最新の検証」を選ぶ。これは模擬会話のライブ表示で、実際のLINE送信や別々の自律AIエージェント同士の実会話を示すものではない。

`docs/simulations/live/persona-events.jsonl` に各実行のお客様、注文担当、統括、店長入力と操作結果、モック配信本文、判定を追記している。各イベントには実行ID、実時刻、`sourceKind: synthetic_persona` が付く。過去実行も保持するため、改善前の失敗と修正後の結果を区別して閲覧できる。2026-10-20再開時のローカル表示APIでは10検証回、3,976イベントを確認した。実顧客の氏名・住所・電話番号・逐語録はこの公開ログへ入れていない。

この合格は定義したケースと期待条件の範囲に限る。確認できなかった画像内容、取得されていない会話、実アカウントへの到達、任意の新しい表現まで証明したものではない。実会話原本の監査結果とは件数を合算しない。
