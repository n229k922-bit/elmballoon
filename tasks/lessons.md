# Lessons

- 顧客向け文面は初回案内・不足項目・回答確認の複数経路で生成されるため、変更時は全経路を同時に確認する。
- 日本語の日付は年の有無、和暦、R表記、区切り文字の揺れを前提に扱う。
- 店長向け操作は短い固定語にし、詳細は統括側の報告文へ集約する。
- 商品指定は画像だけでなく、HPの商品番号・丸数字・全角数字・「○番」表記を正規化して照合できるようにする。
- 商品マスター照合画像は店長・統括への内部通知だけに添付し、お客様向け返信と混在させない。
- 「未定で大丈夫」と案内する項目は、判定処理でも「未定」を回答済みとして扱い、同じ項目を再質問しない。
- 顧客メッセージの締め文を変更した場合は、複数メッセージへ分割する境界文字も同時に検証する。
- 全項目の回答をお願いする顧客向け文面では、内部の承認先を説明せず、正確でスムーズな案内に必要であることを伝える。「未定」「なし」を許容し、負担への配慮も添える。
- 自動返信は内容だけでなく応答速度も接客品質に影響する。短文・不足確認・長文復唱で待ち時間を分け、LINEのローディング表示と実際の遅延を一致させる。
- 店舗説明書をナレッジ化するときは、共通注意と商品固有注意を分け、資料にない耐久日数・返品補償を推測しない。破損相談は一次案内と店長通知を両立する。
- 顧客台帳と注文カルテは分離し、1人の顧客へ複数注文を紐づける。注文項目は値だけでなく、状態・回答元・質問回数・確定状態を持たせる。
- 制作可否の確認前は必要最小限だけを聞き、氏名・連絡先・商品別詳細・支払い・領収書は進捗に応じて後から埋める。
- 確定後の注文内容は直接上書きせず、新旧差分を店長へ示して承認後に反映する。
- LINEの分割送信は生ログを即時保存しつつ、返信判断だけを短時間まとめる。待機処理には世代番号を持たせ、最後の1件以外は返信しない。
- 注文開始・安全・破損返品・緊急連絡は会話統合の待機対象から外し、即時性を優先する。
