# AIマネージャー育成計画

## 実装

- [x] アレンジ・ヘリウム説明書を商品別ケアナレッジとして文書化する
- [x] 高温・火気・薬品・柑橘・取扱い・ヘリウム安全・返品交換の質問を判定する
- [x] 説明書で回答できるケア質問を自然な待ち時間後に自動回答し、注文状態を維持する
- [x] 破損・返品交換に関する連絡はお客様へ一次案内し、店長にも通知する
- [x] 説明書の全ページと回答パターンを検証する
- [x] LINEの自動返信前に公式ローディング表示を開始する
- [x] 初回案内・不足項目・回答確認で自然なランダム待ち時間を設定する
- [x] Webhookは待たせず、返信送信と送信記録を安全にバックグラウンド実行する
- [x] 待ち時間の範囲・ローディング秒数・既存の注文状態遷移を検証する
- [x] お客様向けの初回案内・不足項目案内・回答完了案内から「店長へ」の表現を除く
- [x] 全項目への回答をお願いする理由と、未定・なしでもよいことを配慮ある文面で案内する
- [x] 3つの顧客向け経路で新しい文面と注文状態の遷移を検証する
- [x] 注文フォームの全項目入力必須・空欄時は店長確認へ進めない案内へ修正する
- [x] 「未定」「なし」を有効な回答として判定する
- [x] 商品番号・参考画像・商品タイプ・その他質問を個別に入力確認する
- [x] 全項目回答時だけreview段階へ進むことを検証する
- [x] リッチメニュー文言「注文担当を呼び出します」を新規注文開始トリガーへ追加する
- [x] リッチメニュートリガー時の3分割メッセージを検証する
- [x] HP商品番号・スクリーンショット／参考画像を注文担当の初回ヒアリングへ追加する
- [x] 商品番号の表記揺れを正規化し、HP商品マスターと照合して店長通知へ画像を添付する
- [ ] HP全商品を商品マスターへ移行し、番号・画像の更新手順を用意する
- [ ] 注文ヒアリング項目を一元化し、初回・不足項目・回答確認で文面がずれないようにする
- [ ] カレンダー照会結果を統括報告へ接続し、予定名・重複・空き候補を自動表示する
- [ ] 店長の短い指示（確定／候補1／候補2／確認）を注文状態へ反映する
- [ ] 日付・予算・連絡先の入力パターンをテスト可能にする

## 検証

- [ ] 代表的な注文会話を通しで再生する
- [ ] 不足項目の再質問で重複が起きないことを確認する
- [ ] カレンダー未接続・APIエラー時の案内を確認する

## Review

「注文したい」と「注文担当を呼び出します」が同じ新規注文フローを開始し、既存の会話状態をリセットして3通の案内を返すことをローカル実行で確認した。空欄がある回答はcollectingのまま不足項目を再質問し、全項目を実値・未定・なしのいずれかで埋めるとreviewへ進むことも確認した。初回・不足項目・回答完了の顧客向け3経路から「店長」の表現を除き、全項目が必要な理由と「未定」「なし」を使えることが表示されることを再検証した。自動返信前のLINE公式ローディングAPI、3種類の待ち時間の上下限、WebhookをブロックしないwaitUntil登録、注文開始時の3分割メッセージをローカルテストで確認した。アレンジ1ページ・ヘリウム3ページを画像と抽出文字で照合し、高温・薬品・火気・取扱い・ヘリウム安全・破損返品・日持ちの7種類の質問をテストした。ケア回答後も注文状態が保持され、破損返品だけ店長通知対象になることを確認した。
